# CodeCraft 代码规范

本文件是仓库的编码标准。Cursor Agent 必须遵守 `.cursor/rules/` 中的对应规则；写代码前先读本文件。

## 1. 适用范围

- **产品代码**（本仓库里让用户生成项目、改代码、下载、预览的部分）：必须遵守全文。
- **AI 生成给最终用户的项目**：标识符、UI 文案按产品语言策略；本仓库里的模板与管线代码仍要有「用户层面注释」。

## 2. 语言与文件

- 产品代码迁到 TypeScript，`strict: true`。不要用 `any`；LLM 返回值必须用 Zod（或同等 schema）解析，禁止 `as Blueprint`。
- 标识符（文件名、函数名、类型名、变量名）用清晰英文，表达真实意图：`createGenerationJob`，不要 `doGen`。
- 注释用**简体中文**，写给维护者和产品读者，不写给编译器。
- 不要在注释或 README 里使用「A 级架构」「企业级 SOA」等无法被代码证明的措辞。

## 3. 硬规矩：用户层面注释（必须）

每一段有独立职责的代码，都必须在正上方写注释，回答两件事：

1. **这段代码是干什么的**（业务职责，不是把代码翻译成中文）。
2. **在用户层面上有什么用**（用户能感知到的结果：能生成、能看到进度、失败能重试、密钥不会泄露等）。

必须写注释的位置：

- 每个源文件开头（这个文件帮用户完成什么）
- 每个导出的函数、类、组件、路由、Job 处理器
- 每个会改变用户可见行为的分支（失败重试、权限拒绝、取消生成、校验失败）

不要写的注释：

- 复述代码：`// i 加 1`
- 实现细节当标题：`// 使用闭包把 res.write 注入 logger`
- 评分腔：`// 【A级架构核心】指数退避`

```ts
// ❌ 不合格：只解释实现
// 按 1s、2s、4s 等待后重试 axios
async function callApiWithRetry() {}

// ✅ 合格：职责 + 用户能感到什么
// 调用大模型失败时自动再试几次。
// 用户层面：网络抖动或接口限流时，不必重新点「生成」，这次任务会自己接着跑。
async function callApiWithRetry() {}
```

```tsx
// ❌ 不合格
// 渲染按钮
<button>Generate</button>

// ✅ 合格
// 提交自然语言需求，开始生成项目。
// 用户层面：这是用户从「我想做一个待办」走到「得到可下载项目」的入口。
<button>Generate</button>
```

内部一行纯计算、类型导入、显而易见的赋值，不必每行都注释。但只要这段逻辑构成一个「用户能理解的动作」，就必须有用户层面注释。

## 4. 架构

- 按职责分模块，禁止再往单个上帝类里堆逻辑。推荐落点：
  - `domain`：Job、Blueprint、Patch 等类型与 schema
  - `llm`：模型调用、重试、用量
  - `pipeline`：Architect / Coder / QA 编排
  - `ast`：骨架压缩、语法守卫
  - `workspace`：沙箱读写、路径限制、打包 zip
  - `jobs`：队列、取消、事件
  - `api` / `web` / `cli`：接口、界面、命令行
- UI 与路由不得直接读写磁盘或拼 prompt。必须经过 Service / 模块边界。
- 对外 API 用 Job：创建任务 → 后台执行 → SSE 推送进度。不要把几分钟的生成挂在一次 HTTP 请求上。

## 5. 安全（上线底线）

- API Key 只存在服务端环境变量。禁止浏览器 POST 明文密钥。
- 生成文件必须落在当前 Job 的沙箱目录内。拒绝 `..` 与绝对路径。
- 禁止在控制面服务器上执行用户（或 AI）生成的项目（不要 `exec` `.bat` / `npm start` 生成物）。
- 提供下载 zip 与静态预览；「Run」只允许在用户本机或隔离沙箱。
- 所有外部输入（描述、路径、补丁 JSON、LLM 输出）先校验再使用。

## 6. 测试

- 核心业务逻辑必须有自动化测试（Vitest 或 Jest）。
- 每个被测行为至少覆盖：正常路径、边界、预期错误。
- 测公开行为（用户能感知的结果），不要测私有实现细节。
- 先写失败测试，再写实现（TDD）。没有测试的「核心逻辑」视为未完成。

## 7. 前端

- 产品 UI 使用组件化前端（Vite + TypeScript），不要继续往单文件 `index.html` 堆逻辑。
- 控件必须真正接到后端。禁止展示未接线的勾选框或按钮。
- 生成进度用结构化事件展示，不要把 ANSI 颜色码当协议。

## 8. 提交与文档

- 提交信息说明原因，不用「更新」「aaaa」。
- 用户可见行为变化时，同步更新 README 或相关文档，且表述必须和代码一致。
